# 回测规范

怎么做才算一次可信的回测。评价的数值线在[评价标准](评价标准.md)，本文件只写做法。

## 1. 禁止后视（最高原则）

- 某根 K 线上的决定，只能用这一根**开盘时已经收盘**的数据。
- 信号在收盘确认，成交放在下一根开盘。这不是后视。
- 用当根收盘去改当根开盘就该执行的单，就是偷看。
- 整段历史一次算完时，信号只要读了未来 K 线，这次回测整个作废，不留其余结果。

## 2. 成本

- 手续费：按边收，写明费率（默认永续 taker 每边 0.04%~0.05%）。
- 资金费：能拿到真实资金费就用真实值；拿不到时，**本项目决定只收买卖各 0.05%（来回 0.1%）的手续费，不单独计资金费**，并在报告里写明这是近似。
- 滑点：写明假设值；没有订单簿数据就不虚构滑点测量。
- 压力测试：成本加倍后再跑一次。

## 3. 数据

- 只用 `数据/` 下已登记的文件（见[数据说明](../数据/数据说明.md)），路径用 `--data-root` 指定。
- 不重采样、不补数据、不改价格；缺口和异常不修复，只在报告里写明。
- 同一标的换数据口径（成交价/标记价）结果会变，必须写明用的是哪种。

## 4. 样本划分

- 样本外检验期必须在看结果之前划定，只用一次。
- 选参只能用样本内；样本外期的结果不得再回头改参数。
- 单次留出样本不能替代统计检验，见[评价标准](评价标准.md)第 5 节。

## 5. 试验登记

- 每个策略记录“试验次数 N”：调过多少参数、试过多少变体、含失败的。
- 没有登记 N 的结果不能进入绩效评价。
- 扫参的档位在开跑前写死，不因为边缘最优就加档。

## 6. 输出

- 每次回测输出一个 JSON 到被忽略的 `.cache/`，里面带输入文件的 SHA256。
- 研究结论只写 Markdown，格式见[报告模板](报告模板.md)。

## 7. 常见错误（来自以往教训）

- 引擎 bug 会让整批结论作废；改完必须整批重跑，旧数字不能混用。
- 赢家诅咒：在挑过的标的上看到的好结果，要放回其他标的和滚动验证里再看。
- 高胜率 + 小止盈 = 低盈亏比，不是优势。
- A 段选出的最优参数在 B 段常常变差，只有“邻域整片稳健”才算数。
- 月度“为正”在每月只有几笔时噪声很大，不作为通过条件。
