# 文档目录

先读[项目 README](../README.md)了解这个工程在做什么，再按下表找文档。

| 想知道什么 | 看哪里 |
|---|---|
| 所有策略现在是什么状态、各自的关键数字 | [策略总览](策略/README.md) |
| 某个策略的规则、回测数据、评价表 | [策略/有研究价值/](策略/有研究价值/)（每个策略一个文件） |
| 哪些策略被证明不行 | [已否决](策略/已否决.md) |
| 哪些旧策略在本仓库无法重建、只留档 | [归档](策略/归档.md) |
| 策略凭什么算“好”或“不行” | [评价标准](方法/评价标准.md) |
| 回测该怎么做才可信 | [回测规范](方法/回测规范.md) |
| 新写一个策略文档用什么格式 | [报告模板](方法/报告模板.md) |
| 用了哪些数据、从哪来 | [数据说明](数据/数据说明.md)、[数据清单](数据/数据清单.md)、[排除清单](数据/排除清单.md) |

## 目录结构

```
docs/
├── README.md              本文件
├── 方法/                  怎么评、怎么测、怎么写
│   ├── 评价标准.md
│   ├── 回测规范.md
│   └── 报告模板.md
├── 策略/                  每个策略的状态与数据
│   ├── README.md          策略总览
│   ├── 有研究价值/         一个策略一个文件
│   ├── 已否决.md
│   └── 归档.md
└── 数据/                  数据来源与清单
    ├── 数据说明.md
    ├── 数据清单.md
    └── 排除清单.md
```

## 文档规则

1. 文件名只用中文名称，不带日期、不带序号。日期写在文档开头的“更新”一行。
2. 每个事实只写一处，其他地方用链接指过去。评价线只在[评价标准](方法/评价标准.md)，策略文档不重复。
3. 策略文档格式必须与[报告模板](方法/报告模板.md)一致。
4. 数字必须有回测数据支持；没重跑的旧数字只能写在[归档](策略/归档.md)的“原声称”列。
5. 新增或移动文档时，同步更新本页和[策略总览](策略/README.md)。
